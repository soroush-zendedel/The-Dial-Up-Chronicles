# Lightweight production workflow

Use the episode checklist as the working status record. Skip or remove steps that do not apply.

1. **Choose:** Write the episode's central question and why it matters now.
2. **Gather:** Save a few useful sources and separate verified context from personal memory.
3. **Write:** Draft and revise the Persian source script. When it is stable, adapt it into a separate English script written to sound natural aloud.
4. **Plan the sound and picture:** Note only cues, assets, and visuals that will actually be used. Reuse suitable screen recordings where practical, then align the edit separately to each language's narration.
5. **Record and edit:** Record a separate narration and edit for each language version. Work with local media files; keep large raw files outside Git.
6. **Review:** Check the story, names, English adaptation, rights, captions, and final exports in both languages.
7. **Publish:** Publish the Persian and English videos in separate language-specific YouTube podcast playlists. Record each release date and link in the episode brief. RSS is not required for manual video uploads.
8. **Learn:** After the bilingual pilot, review audience response and the extra production effort before deciding whether to continue regular English releases.

## Episode ending

End each episode with three short beats, aiming for about 30 seconds total:

1. A final reflection that lets the story settle.
2. A one-sentence preview of the next episode, without giving away its central turn.
3. A brief, consistent invitation to suggest improvements to the public project. Point listeners to the [contribution guide](contributing.md) for the full instructions; do not explain GitHub or Codex in detail in every episode.

Use the outro section in the episode template. Replace the next-episode placeholder only when its topic is known. If a beat does not fit an episode, keep the ending natural and short.

Suggested spoken version (adapt freely, and keep the two language versions natural):

> اگر این خاطره چیزی را در شما زنده کرد، پیشنهادتان را به Codex بگویید؛ بعد از بررسی تغییر، از او بخواهید آن را برای بررسی به پروژه بفرستد. راهنمای کوتاهش در توضیحات قسمت است. قسمت بعد درباره‌ی [موضوع قسمت بعد] است. تا آن شب، مراقب خاطره‌های آنلاین‌تان باشید.

> If this story brought something back for you, tell Codex what you think could improve the project. After reviewing the change, ask Codex to send it in for review. There’s a short guide in the episode description. Next time, we'll talk about [next episode topic]. Until then, take care of your online memories.

Planning is successful when it removes uncertainty from the next production step. If a document is not helping, simplify it.
